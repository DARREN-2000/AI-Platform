# 08 — AI (LLMs, Agents, RAG, Evaluation)

## Provider & model abstraction
- MUST access all LLMs through one internal client interface; MUST NOT call provider SDKs directly from app/business code.
- MUST make model, provider, temperature, and limits configurable via env/config, never hardcoded.
- SHOULD support >=2 providers behind the interface for fallback and benchmarking.

## Structured outputs & tool calling
- MUST request structured output (JSON schema / function calling) for any machine-consumed result.
- MUST validate model output against a schema; on failure, MUST repair-or-fail, never propagate unvalidated output.
- MUST define tools with typed, validated arguments; MUST validate args before execution.
- MUST make tools idempotent where possible and side-effect-safe to retry.

## Agents / LangGraph
- MUST model non-trivial agents as explicit state graphs (typed state, nodes, conditional edges).
- MUST enforce max-steps and loop detection; MUST bound total tokens/cost per run.
- MUST route irreversible/risky actions through a human-in-the-loop or approval gate.
- MUST NOT use an agent where a deterministic function or single call suffices.

## RAG & vector DBs
- MUST treat retrieval quality as a first-class, measured component (recall/precision on a fixed set).
- MUST chunk deliberately and store source metadata for citation/grounding.
- MUST ground answers in retrieved context and handle "no relevant context" explicitly.
- SHOULD add reranking only when measured to help; MUST choose vector store by scale/latency needs, not hype.

## Prompt management
- MUST store prompts as versioned files/templates, not inline string literals scattered in code.
- MUST NOT concatenate untrusted input into instructions; separate system/instruction from user data.
- SHOULD keep prompts minimal and test them like code.

## Reliability
- MUST set timeouts, bounded retries (exponential backoff + jitter), and a fallback path on every model/tool call.
- MUST handle rate limits and partial failures gracefully (degrade, don't crash).
- SHOULD cache deterministic/expensive calls keyed on normalized inputs with a TTL.

## Streaming
- SHOULD stream user-facing token output; MUST still validate the final assembled result.
- MUST handle mid-stream errors and cancellation cleanly.

## Evaluation (mandatory for any AI feature)
- MUST maintain a versioned golden dataset (inputs + expected/rubric), including edge cases.
- MUST use layered metrics: deterministic checks first, LLM-as-judge for open-ended quality, human spot-check sample.
- MUST give the LLM-as-judge an explicit rubric and require structured score + reasoning; SHOULD calibrate against human labels and control position/verbosity bias.
- MUST evaluate agents on both outcome and trajectory (tool choice, args, steps, cost).
- MUST run an eval regression suite in CI and fail on drops below baseline thresholds.
- MUST account for non-determinism: pin seeds/temperature where possible, sample N, report variance, set margins.

## Observability
- MUST trace every LLM call, tool call, and node with inputs, outputs, tokens, cost, latency, and a shared trace id.
- MUST make tracing degrade to a no-op when the tracing backend is not configured.
- SHOULD mine production traces back into the eval dataset.

## Safety
- MUST apply input/output guardrails (PII, injection, unsafe content) appropriate to the use case.
- MUST NOT log secrets or full sensitive payloads in traces/logs.
