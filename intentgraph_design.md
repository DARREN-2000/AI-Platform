# IntentGraph - V2 Architecture Design

IntentGraph is the central intelligence and orchestration layer of the Enterprise AI Platform. It is responsible for parsing user intents, planning multi-step workflows (Directed Acyclic Graphs), managing agent memory, and executing tool calls. In V2, it delegates all RAG retrieval to EnterpriseIQ and routes all LLM generation through the Inference Control Plane.

## 2. Package Structure

- **`core.graph`**: The engine for building and executing DAGs based on user intent. Manages transitions between different agent nodes.
- **`core.memory`**: Manages conversation history (short-term) and user preferences/context (long-term).
- **`core.agents`**: Specialized LLM personas/nodes in the graph (e.g., a Planner that breaks down tasks, a Researcher that calls EnterpriseIQ).
- **`core.tools`**: Definitions of functions that the LLM can invoke.
- **`api`**: The web interface (FastAPI or similar) receiving requests from frontends (e.g., Next.js UIs).
- **`models`**: Pydantic models defining the state of the graph at any given node.
- **`clients`**: SDK wrappers for communicating with the Inference Control Plane and EnterpriseIQ.

## 3. Interfaces

- **Client UIs (WebSockets/SSE)**: Receives user queries and streams back intermediate steps (agent thoughts, tool executions) and the final answer.
- **EnterpriseIQ (HTTP)**: Invoked via the `enterprise_search` tool. IntentGraph passes the user's JWT to ensure RBAC is respected during retrieval.
- **Inference Control Plane (HTTP)**: All agent reasoning and text generation calls route here.
- **External Tools (Various)**: APIs for web search, internal databases, or code execution environments.

## 4. Domain Model

- **Intent**: The parsed objective of the user's request.
- **GraphState**: A mutable object passed between nodes in the DAG, accumulating context, retrieved documents, and intermediate answers.
- **Node**: A step in the execution graph (e.g., "Retrieve Context", "Evaluate Answer", "Generate Output").
- **ToolCall**: A structured request generated by the LLM to execute a specific function.

## 5. API Specification

**Base URL**: `/api/v1/orchestration`

- `POST /sessions`: Create a new chat/agent session.
- `POST /sessions/{session_id}/message`: Send a message to the agent. Often uses SSE to stream back the execution trace (e.g., `{"type": "tool_start", "tool": "search"}`).
- `GET /sessions/{session_id}/history`: Retrieve the conversation and execution history for a session.

## 6. Database Schema (PostgreSQL/Redis)

- **`sessions`**: `id`, `user_id`, `tenant_id`, `created_at`, `status`
- **`messages`**: `id`, `session_id`, `role` (user/assistant/tool), `content`, `metadata` (tool call details)
- **`graph_state_checkpoints`**: Used for fault tolerance and "time-travel" debugging. Stores the serialized `GraphState` at each node transition.

## 7. Event Model

- **Publishes**: Emits telemetry events for agent execution paths (e.g., `agent.node.completed`, `agent.tool.failed`) to the central observability stack.
- **Subscribes**: None natively, though it could listen to long-running asynchronous tool completion events.

## 8. Deployment Model

- **Execution Engine**: Stateless, scalable workers processing incoming intents.
- **State Management**: Heavily reliant on Redis or PostgreSQL to persist the `GraphState` so that long-running graphs can survive worker restarts.

## 9. Testing Strategy

- **Unit Tests**: Test the DAG execution logic with mocked LLM responses to ensure state transitions correctly under various scenarios (success, tool failure, loop detection).
- **Integration Tests**: Verify the `inference_client` interacts correctly with the Inference Control Plane API and handles rate limit responses.
- **E2E Tests**: Run specific "Golden Path" intents through the system, mocking external APIs but allowing actual prompt generation to evaluate agent stability.

## 10. Roadmap

1.  **Phase 1**: Separate any remaining Next.js UI code into a distinct frontend repository.
2.  **Phase 2**: Standardize the DAG execution engine (potentially adopting LangGraph or a custom NetworkX implementation tailored for the platform).
3.  **Phase 3**: Migrate all LLM calls to use the Inference Control Plane SDK.
4.  **Phase 4**: Implement the JWT pass-through mechanism for the EnterpriseIQ tool.
5.  **Phase 5**: Build a robust checkpointing system to pause, resume, and debug agent workflows.
